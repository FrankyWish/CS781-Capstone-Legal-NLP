# Phase 1: legal language-model pretraining

**Task.** The task was to take a 512-word prompt from an Indian legal document and generate the next 128 words. There were 1,000 test prompts. The main evaluation metric was BERTScore F1 (`roberta-large`), with ROUGE-L and BLEU-1..4 as secondary metrics. The model had to contain between 50M and 300M parameters, be trained from scratch on the provided corpus, and use four substantially different architectures.

**Result.** Got Rank 1 with a score of **0.8689**, which was 0.0171 higher than the second place. The final submission was a hybrid system. Out of 1,000 continuations, 308 were retrieved directly from the permitted corpus and the remaining 692 were generated by the models. The generation-only score was **0.8449** using MBR over three models. This is the score that actually shows how well the models performed.

## Architecture

| | **M1 `LexArc-D`** | **M2 `LexArc-ED`** | **M3 `LexArc-L`** | **M4 `LexArc-P`** |
|---|---|---|---|---|
| mechanism | decoder, GQA 12 query : 4 KV heads | encoder-decoder | decoder, MLA (latent 256) | decoder, GQA + pointer-generator head |
| layers | 16 | 10 enc + 8 dec | 16 | 16 |
| parameters | 125.9M | 151.0M | 129.0M | 126.0M |
| file | `cs781_model.py` | `cs781_model_ed.py` | `cs781_model.py --attn mla` | `cs781_model_ptr.py` |

All four models share d_model 768, 12 heads of 64, SwiGLU hidden 2048, RoPE (theta 10,000), RMSNorm, context length 1,024, vocabulary size 32,768 and tied embeddings.

I also tried three modifications to a LLaMA-style block. Each one was controlled using a config flag and tested separately at 34M parameters using `ablate.py`.

- **Value residual:** Layer-0 values are mixed back through a learned gate. This improved the result by 0.024 nats.
- **QK-norm + z-loss 1e-4:** This gave the biggest improvement of 0.259 nats and also allowed a 3 to 5x higher learning rate.
- **4 register tokens:** This actually made the result worse by 0.022 nats, so I kept it as a failed experiment.

Muon also performed much better than AdamW at the same number of tokens, with a difference of 0.486 nats. This was the largest individual improvement I measured.

M2 uses `CE(decoder) + 0.3 * MLM(encoder)` as its training objective, so the encoder also receives gradients during training.

M4 uses a pointer-generator head:

`p(y) = g * p_vocab(y) + (1 - g) * sum of attention on earlier copies of y`

The calculation is done in log space. My first implementation used probability space, but it started producing NaN values after around 700 steps.

## Pipeline

1. **Tokenizer and corpus** (`cs781_bpe.py`, `build_corpus.py`, CPU, 40 min)

   I made my own byte-level BPE tokenizer by extending the course A-1 implementation. It uses legal-aware pre-tokenisation, which splits digit groups and punctuation so that `Act`, `Act,` and `Act.` are treated as the same type. Documents below 900 words were removed, as most of them were just case headers.

   The final corpus had 1.255B tokens:
   - SC: 254.7M
   - HC: 450.0M
   - Tribunals: 400.0M
   - Acts: 150.0M

   I also kept a 500-window dev split in the exact test format, separated using document hashes.

2. **Data mix**

   I trained a Naive Bayes source classifier which got 86.5% accuracy on the held-out data. It showed that around 87% of the test prompts came from the Supreme Court source. Because of this, the training data mix was gradually changed from 35% SC to 70% SC and finally 100% SC during the last 10% of training steps.

3. **Training** (`train_phase1.py`, `train_ed.py`, 6 hours each, around 586M to 680M tokens)

   Before starting the actual training, I added a few checks to catch implementation mistakes:
   - G1 checks the input-to-target shift.
   - G2 checks whether the model can overfit a single batch.
   - G3 compares KV-cached decoding with a full forward pass.

4. **Decoding sweep** (`score_and_submit.py`)

   I tested different checkpoints (`best`, `final`, weight soup) with different temperatures, top-p values, repetition penalties, no-repeat n-grams and prompt-copy bias settings. These were compared using dev BERTScore with a bootstrap interval. Every generated continuation was adjusted to exactly 128 words.

5. **MBR** (`ensemble_mbr.py`)

   I generated 6 samples each from M1, M3 and M4. From the candidates, I selected the one with the highest expected BERTScore against the other 17 candidates. This improved the dev score by +0.0068 compared to the best individual model.

6. **Supreme Court continued pretraining**

   M1 and M3 were trained for another 4 hours using `train_phase1.py --init`. `M1_SC`, trained with the full learning rate, became the main model used as a starting point in most of the later phases.

7. **Retrieval** (`retrieve_phase1.py`, CPU, 10 min)

   I used an Aho-Corasick automaton on the last 20 words of each prompt to find matching prompts in the corpus. If a match was found, the next 128 words from the corpus replaced the generated continuation. I also tested six different candidate offsets for each prompt.

## What moved the score

| **change** | **test BERTScore** |
|---|---:|
| pilot, 55M tokens | 0.8308 |
| M1, 586M tokens, raw decoding | 0.8359 |
| + decoding sweep | 0.8384 |
| MBR over M1 + M3 + M4 | 0.8449 |
| + retrieval, 40-word needle (152 matched) | 0.8592 |
| + 25-word needle (241) | 0.8659 |
| + 20-word needle (263) | 0.8667 |
| + multiple candidate offsets (308) | **0.8689** |

The four architectures ended up with quite similar scores (0.8346 to 0.8386 test) when compared at equal compute. Increasing the number of training tokens by 10.6x only improved the score by +0.0051. I also tried task-format SFT using `sft_phase1.py`, but it did not give any improvement.

## How to run

```bash
python build_corpus.py
# CPU, ~40 min: tokenizer, shards, dev split

python train_phase1.py --model M1_LexArcD_full --hours 6.0

python train_ed.py --model M2_LexArcED --hours 6.0

python train_phase1.py --model M3_LexArcL --attn mla --hours 6.0

python train_phase1.py --model M4_LexArcP --pointer --hours 6.0

python train_phase1.py --model M1_SC --init M1_LexArcD_full/ckpt/final.pt --mix sc --hours 4.0

python score_and_submit.py --model M1_LexArcD_full
# checkpoint + decoding sweep, ~35 min

python ensemble_mbr.py --models M1_LexArcD_full:soup.pt M3_LexArcL:best.pt M4_LexArcP:best.pt --k 6

pip install pyahocorasick

python retrieve_phase1.py --split test --words 20 --base MBR/gen/prediction.json
# final hybrid zip
```

Seeds used were 1337 for training and 1337/0/7 for corpus, sweep and MBR respectively. The corpus, tokenizer and dev split can be reproduced byte-for-byte. Training results can have small differences because of cuDNN non-determinism.

| **file** | **role** |
|---|---|
| `cs781_bpe.py` | byte-level BPE, legal pre-tokenizer |
| `build_corpus.py` | tokenizer training, uint16 shards, dev split |
| `cs781_model.py` | M1/M3 model, Muon optimiser |
| `cs781_model_ed.py`, `train_ed.py` | M2 and its trainer |
| `cs781_model_ptr.py` | M4 pointer-generator head |
| `train_phase1.py` | gates, wall-clock LR schedule, data-mix phases, generation, zip |
| `score_and_submit.py` | checkpoint and decoding sweep |
| `ensemble_mbr.py` | candidate pooling and MBR |
| `retrieve_phase1.py` | corpus retrieval hybrid |
| `foundation_check.py` | held-out SC likelihood of every checkpoint |
| `ablate.py` | 34M-parameter ablations of the shared modifications |
| `sft_phase1.py` | task-format SFT (null result) |
